# 운영자 검토를 마치기 위한 최소 결정

**확인된 내용**

- 사업자가 아닌 개인 운영이며, 사용자가 운영자·개인정보 담당자의 공개 이름을 **조민제**로 확인했다.
  가상의 상호·사업자등록번호·사업장 주소나 담당 부서를 만들지 않는다.
- 지원·개인정보 문의 이메일은 superriaco@gmail.com을 계속 사용한다.
- 현재 앱/서버의 가입 동의·프리셋 제한은 운영 반영/검증됐다. 계정 삭제 0024와
  관련 Edge Function 3개도 운영 배포됐다. 전용 시험계정 2개의 실제 비밀번호·무인증 재개 삭제도 검증됐다. 다만
  Google·Apple 재인증과 실제 음성 재접속 검증까지 완료됐다는 뜻은 아니다.
- 이 문서군은 미게시이며 현행 법적 문서와 동의 버전을 바꾸지 않았다.

## 승인된 보유·파기 기준과 남은 게시 결정

- 사용자가 이번 작업 백업을 **검증 종료 후 7일 이내, 늦어도 2026-11-18 파기**하는
  기준을 승인했다. 검증이 그때까지 끝나지 않으면 만료 전에 사유·새 만료일을 기록한다.
  승인 사실과 실제 파일 파기는 별개이며, 담당 에이전트가 대상·파기를 확인한다.
- 사용자가 완료된 지원·삭제 요청 메일을 **요청 종료 후 90일**, **월 1회 수동 정리**하는
  기준을 승인했다. 자동 purge 설정이 적용됐다는 뜻은 아니다. 미완료 요청은 해결까지
  보관하며, 정리 주기에 따른 실제 파기 시점을 최종 고지에 반영한다.
- 계정 삭제 영수증은 30일 조회 / 정상 일일 정리 기준 30~31일로 운영 반영됐다.
  같은 정리 명령의 실제 pg_cron 시험 실행도 성공했다. 정기 실행 감시는 운영 절차다.
- **게시 일정은 아직 미승인**이다. 조건부 제안은 공고 2026-11-12 / 시행 2026-12-12다.
  로그 처리 계획·제공자 고지와 최종 기능 검증을 마친 경우에만 적용하며 공고가 늦어지면
  일정을 다시 잡는다. 개인정보 처리방침과 이용약관의 변경 내용을 함께 공지한다.

## 새로 확인된 준비 상태

- Resend의 `minestero.com` 도메인이 인증됐고, 해당 도메인 전용 SMTP 자격증명으로
  Supabase SMTP(465)를 연결했다. 도쿄(`ap-northeast-1`) 발송이며 이메일 메타데이터·
  로그·API 기록을 포함한 계정 데이터는 미국 저장이다. 가입 확인·복구 메일 2건이
  전달됐고 사용자도 수신을 확인했다. PKCE 교환과 가입 동의 기록 검증도 완료됐다.
  초기 Full Access 설정 키는 폐기됐다. 열람·클릭 추적은 사용하지 않는다. Osol 앱의 인증 메일 기능은 수신 메일을 처리하지
  않는다. 기존 루트 도메인의 Enable Receiving ON 설정은 유지됐다.
  지원·삭제 요청 이메일은 계속 Gmail이다.
- 새 지도 자산 프록시는 운영에서 응답하며 공개 자산 검사 13개와 PR149 병합이
  확인됐다. 228 베타는 Android APK·iOS 내부 TestFlight로 배포됐으며, 이전 설치본의 r2.dev 요청 종료와 실기기 확인은 별도다.
- 삭제 0024와 `delete-account`, `apple-delete-callback`, `livekit-token`은 운영 배포됐다.
  완료 시 계정·음성 룸 식별자를 모든 작업 별칭에서 함께 지우고 `pg_cron` 일일 작업
  (UTC 03:17)으로 30일 경과 완료 기록을 정리하는 계약이다. 같은 정리 명령의 실제 pg_cron 실행과 전용 시험계정 2개의 삭제가 검증됐다.
  원래 일일 작업(17 3 * * *)은 유지됐다. Apple Return URL은 사용자가 추가했다.
  실제 Google·Apple 인증과 미디어 재접속 검증 완료로 확대 해석하지 않는다.

### 승인·집행 상태 및 남은 검토안

| 결정 | 검토할 제안 | 승인 후 확인할 집행 |
|---|---|---|
| 이번 운영 작업용 백업 | **운영자 승인됨:** 현재 작업 검증 종료 후 7일 이내, 늦어도 2026-11-18 파기. 그날까지 검증이 끝나지 않으면 만료 전에 사유와 새 만료일을 기록 | 대상 파일 목록·파기 완료 기록, 복구 시 삭제 요청 재적용 절차 |
| 지원·삭제 요청 메일 | **운영자 승인됨:** 요청 종료 후 90일에 원문·첨부 정리. 진행 중인 요청은 해결까지 보관. 분쟁 등 별도 보관이 필요하면 항목·사유·종료 기준을 따로 기록 | 월 1회 정리, 완료일 표시와 삭제 점검 기록. 현재 Gmail 설정이 이를 자동 시행한다고 표현하지 않음 |
| 운영 로그 | 읽기 전용 조사에서 VM 컨테이너 로그의 회전/만료 설정이 확인되지 않음. 제공자별 실제 로그·기본 보유기간 조회 후 확정. 운영자가 제어하는 별도 원문 요청/토큰 로그는 새로 만들지 않음 | 제공자별 설정·회전 가능 범위와 삭제 절차를 표에 기록. 임의 공통 보유기간을 약속하지 않음 |
| 문서 일정 | 공고 2026-11-12 / 시행 2026-12-12 후보 유지. 전제조건 미충족 또는 공고 지연 시 날짜 재승인 | 최종 보유표·제공자 고지·배포 검증 후 새 고정 HTML/해시/앱·서버 동의 버전 순서로 공개 |

7일·90일은 사용자가 승인한 운영 기준이며 법정 기간 산정이나 자동 정리 설정이 아니다.
공고·시행일은 아직 제안이다. 승인만으로 집행 완료를 표시하지 않으며, 정기 정리 시점에 따른 실제 파기 범위를 최종 고지한다.

## 사용자가 직접 채울 설문으로 돌리지 않을 조사

- 계약 법인·제공자별 처리 국가/항목/기간/이전 근거는 실제 계정과 공식 계약 자료를
  담당 에이전트가 조회해 표로 준비한다. 필요한 로그인·계약 접근만 요청한다.
- 지원 이메일의 회신/완료 안내 방식은 이미 공개한 요청 페이지와 일치하게 준비한다.
- 새 앱 설치·실제 로그인·마이크/푸시/위치 등 기기 검증은 가능한 실제 기기에서
  진행하되, 시뮬레이터·관리자 생성 테스트계정 성공으로 대신 완료 처리하지 않는다.

## 새 동의 버전 배포 순서

1. 후보 문안·변경표·담당자·보유표·제공자 고지와 공고/시행 일정을 승인한다.
2. 신규 고정 문서 경로(제안 `legal/privacy/2026-12-12.html`,
   `legal/terms/2026-12-12.html`)를 만들고 정확한 HTML 해시를 기록한다.
   날짜 확정 전에는 해당 파일이나 manifest항목을 만들지 않는다.
3. 공고 후 실제 URL·HTML·해시·이전 버전 링크를 확인한다.
4. Flutter가 새 문서·버전을 지원하도록 준비하고, 기존 앱이 어떻게 안내될지 검증한다.
   현행 앱은 버전 문자열을 정확히 비교하므로 서버만 먼저 바꾸면 이전 앱이 막힌다.
5. 시행일에 서버 정책과 앱의 실제 지원 범위를 맞춰 반영한다. 기존 동의 이력을
   새 문서에 동의한 것으로 덮어쓰지 않는다. SQL·앱 변경은 별도 검증/배포한다.

- 같은 지침의 담당자 항목은 개인정보 보호책임자 성명 또는 관련 업무·고충을 담당하는
  부서/연락처를 다룸. 전화와 이메일을 모두 쓰는 것은 권장으로 구분되며 없는
  전화번호나 회사·주소를 꾸며내는 근거가 아니다. 사용자가 공개 담당자명을 조민제로 확인한 사실을 반영했다.
- [Apple 계정 삭제](https://developer.apple.com/support/offering-account-deletion-in-your-app/), [Google Play 삭제 요청](https://support.google.com/googleplay/android-developer/answer/13327111): 앱 내 경로/독립 웹 요청, 처리 기대·완료 안내, 관련 데이터와 Apple 연결 해제를 검토.

법적 적합성이나 심사 승인을 받았다는 문서가 아니다. 기술 확인·운영자 결정과
법률 검토가 필요한 판단을 분리한다.
